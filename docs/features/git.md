# Git、工作树与拉取请求

在对话里使用 Git：分支签、改动计数和 Git 面板，每个对话可以在自己的工作树里改（内置插件 `plume.git`，随应用提供、不能停用）；以及多平台的拉取请求查看与审查（插件 `plume.pull-requests`）。代码审阅流程见 [多会话协作](multi-session.md#代码审阅)。

## 分支签与改动计数

- 输入框上方、项目旁边写当前分支，以及和远端跟踪分支差几个提交（`↑3 ↓1`）。点开可搜索、切换分支，远端分支也能直接检出；git 拒绝切换时原样说明原因。
- 输入框上方右边是还没提交的 `+增 −删`，agent 改文件时跟着变；点它打开 Git 面板。
- 只在 git 项目里出现：项目目录是仓库、底下放着仓库，或 git 读不了它（这时说明原因）。不属于任何项目的聊天里没有。
- 对话在自己的工作树里时，分支签换成工作树签。

## Git 面板

面板区开始页选 Git，或按 ⌘⇧R（Windows 上 Ctrl+Shift+R）。在项目里才列出；项目还不是仓库时，面板里是「初始化仓库」和「让 Agent 处理」。面板看的是下一轮要用的目录（还没发消息的新对话就是所选项目）。

- **改动**：已暂存在上、未暂存在下，平铺或按目录看；每个文件可展开 diff、暂存、取消暂存、丢弃；图片画成图。文件行可「预览工作区文件」，在只读文件面板打开（Word、表格、SQLite 用文档预览）；暂存项同样打开当前磁盘内容。
- **diff 评论**：点 diff 的行号评论这一行，按住拖动或 Shift 点评一段；评过的行号换成序号，点它改或删。评论攒在底下「N 条评论」一条里，可清除或「发给 Agent」：连同那几行 diff 交给面板所在的对话——输入框空着就直接发出，有没写完的草稿就接在后面等人发；新对话交给当前输入框。弹出的面板窗口转交主窗口处理。评论只在内存里，重启就没了。
- **历史**：提交列表旁画分叉和合流，点开一个提交看改了什么。
- **分支**：本地和远端分支，新建、切换、删除；任意两个分支比较。工作区里有多个仓库或工作树时顶上可切换。
- 顶上一行是拉取、提交与推送、获取三个按钮，值得按的那个加重；网络卡住时再按一次就停；后台的静默获取也能停。
- **提交与推送**：弹窗写提交说明，留空则让默认模型按暂存改动写一句（语言可选）；可以顺手提交到新分支，提交后接着推送。
- 操作失败在窗口顶上弹提示；git 读不了仓库时写明原因，可一键把诊断请求写进输入框。
- diff 不做语法高亮。外观页的「+/- 标记」设置作用于这里的改动显示。
- 需要本机装 git 并在 PATH 里（Windows 上按 PATH 找 `git.exe` / `git.com`）；推送、拉取用用户自己的 git 配置和凭据，插件不保存账号信息。

## 工作树

- **新对话的开关**：项目是 Git 仓库时，输入框上方分支后面有「工作树」开关，只在发第一条消息前出现，按项目记、发出第一条时用掉，默认不开。开着发出第一条消息，对话就在新建的工作树里跑：分支 `plume/session-<编号>`，从项目当前分支切出，目录放在工作树根目录下；项目是仓库子目录时，对话落在工作树里的同一子目录。
- **建议新会话的卡片**上的工作树开关同样有效，从卡片开出的会话不用输入框上的开关。
- **工作树签**：⑂、分支名、和基分支差几个提交（`↑2 ↓1`）；同步停在冲突上时多一个琥珀色记号，目录被收走时变灰。点开菜单：
  - **合并到基分支**：先要求提交。基分支检出在项目目录里就在那里合，有冲突立刻退回，不在检出里留半截合并；基分支哪里都没检出时直接算出结果移动分支；检出在别的工作树里时拒绝并说明在哪。合并后可「归档这个对话」。
  - **从基分支同步**：把基分支的新提交合进工作树。有冲突时列出文件，可以「交给这个对话解决」（以人的身份把请求发给这个对话，在跑时排队）或「放弃这次同步」。
  - 对话在跑时这两项都不能做；都不推送。还可以在访达里显示工作树。
- **侧栏 ⑂**：有工作树的对话空闲时，侧栏行首的空心圈换成 ⑂，悬停说出分支。
- **收回和检出回来**：删除、归档对话时收走目录（分支上的提交都已在基分支里时连分支一起删，否则保留）；有未提交改动时不收。取消归档、或下一轮开始时目录不在，就在原处检出回来；检不出来时对话退回项目目录里跑。删除确认框写明会留下什么（未提交文件的完整路径、未合并的提交在哪个分支）。
- **没建成时**：要了工作树却没建成（如 git 报错），对话在项目目录里跑，输入框上方一直有琥珀色提醒，点开是说明和 git 原话。
- **设置 › 工作树**（「代码与版本控制」组）：工作树建在哪（默认数据目录下的 `worktrees`，相对路径从家目录算）、建之前是否先获取远端（不等凭据，最多等 20 秒）、是否自动清理旧的（默认关；只清插件建的、干净的、没有对话在用的，分支保留）；列出各项目的工作树，可在访达显示、删除（有未提交改动时 git 会拒绝）。
- 合并到未检出的基分支需要 git 2.38 以上。工作树的提交写进主仓库的 `.git`（在项目目录外），帮我批准模式下 agent 在工作树里 `git commit` 会被沙箱拦下并申请提权。

## 拉取请求

插件 `plume.pull-requests`（从插件市场安装）：

- 支持 GitHub（含 Enterprise）、GitLab（含实例子路径和子组）、Gitee、Gitea / Forgejo，多账号和自建实例。
- **账号**：设置 › 代码托管，选平台、填服务地址和个人访问令牌；先验证再保存，表单里写明需要的令牌权限和创建链接。停用账号只暂停读取；退出账号删除保存的令牌。
- **列表**：侧栏「拉取请求」页，分「等你审查」「由我创建」「之前已审查」，可按账号、标题、仓库、分支或编号筛选。页面可见时每 45 秒刷新，切回窗口或恢复联网时检查是否过期；更新过的行短暂高亮，未读的带小点。Gitee 只扫描最近推送的 20 个仓库，且没有「已审查」分组；GitLab 的「已审查」在部分实例上不可用。
- **详情**：摘要、检查、活动三段可折叠；「代码」按文件展开 diff（最多 300 个文件、每个文件 4000 行）。宽窗口双栏，窄窗口用返回按钮切回列表。
- **评论和审查**：页面底部发评论、批准、请求修改；提交前确认账号、仓库、编号和正文，请求修改必须写理由；失败保留草稿，切换 PR 不会发错。不合并 PR、不推送、不改本地仓库。
- **交给 agent**：「询问 Agent」「让 Agent 审查」在匹配的本地项目（没有时用插件准备的临时目录，只放 `PR.md`，不自动克隆）里打开空白对话，填入 PR 地址和参数；已有草稿保留，需人发送。agent 只有只读工具 `read_pull_request`（详情和 diff），PR 内容按不可信外部资料处理。
- **环境卡片**：当前分支的 PR 在环境卡片里显示一节，带检查状态，点了去拉取请求页选中它。
- 网络：走系统网络栈和系统代理，不自动重定向、不共享浏览器 Cookie；普通请求 30 秒、diff 60 秒超时；JSON 最多 8 MiB、diff 24 MiB、头像 512 KiB，超限报错。头像只接受已知头像服务或配置的实例源，拿不到时显示首字。
- 令牌经 `plume.secrets` 加密存在插件私有目录，界面读不回已保存的令牌。
