# 审批与权限

这部分决定 agent 的哪些操作直接执行、哪些先问人：权限模式、审批卡、命令沙箱与提权、计划模式和向人提问。

## 权限模式

三档，在输入框上的权限签或设置 › 常规的「权限」里切换，改的是全局设置：

- **请求批准**：编辑文件和运行会改动东西的命令时始终询问；命令跑在只读沙箱里。
- **帮我批准**（默认）：命令在沙箱里直接运行，只对检测到的风险操作请求批准（递归删除、强制推送、写到项目外等）；沙箱只允许写项目目录和临时目录。
- **完全访问**：不再逐项请求批准，可不受限制地访问网络和电脑上的任何文件。开启前弹确认框，说明对文件、终端与 Git、网络与插件的影响。

项目的 `.plume/config.json` 随仓库提交、别人克隆就带过来，所以它只能收紧权限、不能放宽：权限模式只认比本机设置更严的一档（本机帮我批准时项目可以要求请求批准，不能要求完全访问；认不出的值也不认），`alwaysAllow`（「以后不再问」的名单）一律不认。不认的键在打开这个项目的会话里提示一次，设置 › 常规页头的项目配置卡也逐个写明「会放宽权限，已被忽略」；要放宽只能人在本机的设置里改、在审批卡上点。项目收紧了权限模式时，项目配置卡写明全局值被覆盖、不生效；这个项目里的会话，输入框的权限签显示项目要求的那一档，图标换成带锁的文件夹，悬停提示和菜单顶上写明是 `.plume/config.json` 要求的。菜单照旧改本机设置（勾打在本机那档上），在这个项目里不会比项目那档宽。项目配置改了以后，签在下一次读这个会话的设置时跟上：开始新的一轮、界面头一次读这个会话（重开应用后打开它）、在菜单或设置里换本机的档、打开设置 › 常规（读到这个项目的配置卡）、窗口回到前台（在编辑器里改完配置切回来）都算；不盯着文件。

无论哪一档：申请离开沙箱运行（提权）只认人在卡上的回答，或代管这个会话的插件转达的回答（见 [多会话协作](multi-session.md)「插件代管的会话」）；钩子、自动审核和「以后不再问」都不算。提问、计划、MCP 表单这类要人给答案的卡不是审批，权限档管不着，见下面「审批卡」最后一条。

## 审批卡

- 审批卡压在输入框正上方，按钮是拒绝、以后不再问、允许一次；edit 的审批卡正文是 diff。工具卡片上只标「等待确认」。
- 帮我批准命中风险规则时，理由写在卡片正文上方的一段里。
- 同时有多个审批时排队，一次一张，卡上写后面还排着几张（+N）。
- 超时：审批 5 分钟，到时按拒绝处理；要人给答案的卡 30 分钟。卡上有倒计时。
- 子会话（子 Agent、侧边聊天）的审批卡也压在主输入框上方，正文上方写「来自「标题」的请求」。
- 侧栏行首显示等批准的状态点；运行行写「等待你的批准」，要人给答案的写「等待你的回答」或插件给的那句状态（「等你批准计划」）。窗口不在前台时发系统通知。
- 「以后不再问」：插件的会改动工具记工具名；内置浏览器按站点或文件记；MCP 工具记单个工具；读项目外的位置按项目记。
- 「以后不再问」按提出这次批准的一方分开记：插件的工具问的记在那个插件名下，只放行这个插件的工具再问同一件事，别的插件问同样的命令、路径照样弹卡；读项目外、读密钥这类由 Plume 自己守的边界记在 Plume 名下，所有工具共用这一份，插件的批准替不了它。记在本机设置文件（`~/.plume/settings.json`）的 `alwaysAllow` 里，每条写明属于哪个插件（没写插件的是 Plume 自己的）；项目配置里写的不算。插件停用、卸载后它名下的批准留着，再启用、重装后照旧有效。
- 设置 › 常规 › 权限的「以后不再问」一行列出所有答过的批准：批的是什么（命令、文件路径、站点、工具名原样写；Plume 自己的读项目外写成「读取 <路径>」），下面一行是属于哪个插件（插件的显示名）或 Plume。每条可以「撤销」，也可以「全部撤销」；撤销后下次遇到同样的操作重新弹卡。
- 插件代管的会话里，卡（审批、提权和要人给答案的卡）也可以由代管插件替人答，挂在这个会话下面的子会话弹的也算，人和插件谁先答算谁的；插件答的那次调用底下写「由 X 代答」。「以后不再问」插件答不了；人停止代管时已经弹着的卡，之后只能人答。
- 提问卡、计划卡、MCP 表单不是审批，是工具停下来等人给答案：和审批卡同排一队、同一位置、同样过期和随停止撤掉，但权限档、「以后不再问」、自动审核和钩子都不替人答，也拦不下它们（代管这个会话的插件能替人答，见上一条）。画它的插件不在了（停用、出错）时，卡上只有标题和「不答」。

## 帮我批准的风险规则

内置插件 `plume.approval`，随应用提供、不能停用：

- **命令**：递归删除和强制通配删除（项目内相对路径、系统临时目录、同一脉的会话——子智能体、侧边聊天、分叉、建议开出的新会话和它们的来源——的临时目录除外；别的会话的临时目录照样问）、删根目录或家目录；强制推送、`reset --hard`、`clean -f`、`checkout .`、`rebase`；`sudo`、关机、格式化、`dd`、`chown`、改系统服务和定时任务；下载并直接执行（`curl … | sh`、`irm … | iex` 等）；读写密钥文件；写系统路径和 shell 启动文件；上传本机文件；发布包、清理 docker、删集群资源；用 `open` 启动程序；PowerShell / cmd 的递归删除和 Windows 危险程序（`Format-Volume`、`Set-ExecutionPolicy`、`reg delete`、`Start-Process -Verb RunAs` 等）。
- `env`、`xargs`、`bash -c`、`eval`、`find -exec`、`powershell -Command`、`-EncodedCommand`（解码后判）、`cmd /c` 包着的命令按里面那条判断。
- shell 可能是 PowerShell 的地方，一行命令按 bash 和 PowerShell 两种语法各判一遍，任一种读出危险都问人。
- **写文件**：写项目外（系统临时目录和同一脉的会话的临时目录除外）、写敏感路径、改 shell 启动文件。
- **读**：读工作区外的一律问人。
- 不判网络请求和 MCP 工具：网页读取只发 GET、不弹审批；MCP 工具按它们的注解单独处理。
- 本机密钥名单（读取要问）包括数据目录里的 `settings.json`、`credentials.json`、`vault.key`。

## 命令沙箱与提权

本体负责（`packages/core/sandbox`，权限模式对应哪一档、提权、只读都在本体，跑命令的工具换掉了也照样成立）：

- 三种模式：只读（除 `/dev/null` 一概不许写）、能写项目目录和临时目录、不设限。
- macOS 用 Seatbelt；Windows 用受限令牌（只管住一部分：给 Everyone 写权限的位置仍可写；只读模式也给一个按工作区分的私有临时目录）。给不了要求的模式时报错，不会不加沙箱就跑。
- shell 按权限模式选：Windows 上受约束的命令跑在 PowerShell 里，完全访问跑在 Git Bash 里；环境变量 `PLUME_SHELL` 可覆盖。
- 命令的环境向登录 shell 要一份，从图标启动也能找到用户装的工具；分页器、颜色、交互提示都关掉。停止时连同子进程一起停（Windows 用 `taskkill /T /F`），不弹控制台窗口。
- 命令被沙箱拒绝时，模型可以申请提权重试一次；提权总是问人，只管这一次。

## 计划模式

内置插件 `plume.plan`（随应用提供）：

- **开关**：输入框底下权限旁边的计划模式开关，按会话记；新对话里拨了，第一句话发出时跟着新会话。`/plan` 切换开关，`/plan 要规划的事` 先开计划模式再发出后半句。
- **不改文件**：开着时写、改文件的工具（内置的 `write`、`edit`，别的插件声明成写、改文件的也算）由本体直接拒绝，命令一律在只读沙箱里跑（和权限档无关），提权申请不跑；联网和其他插件工具照常。这个会话派出的子 Agent、侧边聊天同样受限。
- **交计划**：模型用 `submit_plan` 交一份 Markdown 计划，输入框上方弹出计划卡，完全访问也不替人批；转录里读作「提交计划 <标题>」。计划卡标题行有倒计时。
  - **接受**（⌘↵）：计划模式关掉，同一轮接着做；请求批准档下多一个「接受并开启自动模式」（⇧⌘↵），先切到帮我批准再做。
  - **在新会话里执行**：计划连同评论存成文件，在同一项目里开一个只带这份计划的新会话去实施，原会话停下；按钮旁的箭头给新会话选模型，不选用默认模型。开不出来时提示。装了会话互通插件时，新会话拿不准计划意图会先读、再问原会话。
  - **修改…**（Esc）：写下要怎么改，模型改完再交。
  - **拒绝**：这一轮停下。
  - 窄窗口下计划正文画在卡里。
  - 卡窄（右栏开着）时按钮上不画快捷键的键帽，常见的一排放得下一行；放不下时接受那一组（接受和主按钮）一起换到下一行、靠右，主按钮不会一个人落下去。
- **计划文件**：每次批准存进会话临时目录的 `plans/plan-<批准时刻>.md`，批准结果里写上路径。
- **计划面板**：交计划时右侧自动打开一次，按 Markdown 显示。等审批时划一段字可以留评论，评论带序号列在计划卡上：「修订」连同补充的话发回去改；直接接受时评论作为「执行时注意」随计划交出。批准过多份时可以切换着看；环境卡片的「计划」一节逐份列出，点一行在面板里打开。
- **压缩后不丢**：批准的计划在上下文压缩时原样接进摘要头；交给新会话的那份写明不在这里执行。
- **别的插件读批准的计划**：经服务 `session.plan` 拿「这个会话照着做的那份」（连同注意事项）：会话自己最后批准、没交出去的那份；在新会话里执行时，那份归新会话，原会话不再算它。
- 开着时系统提示词多一段计划模式规则；一轮查过东西却把方案写在正文里、没交计划时提醒一次（问过人的那一轮不提醒）。提示词里点名的记清单、问人的工具按它们声明的类别找，那个插件没装时不点名。

## 向人提问（`ask_user`）

内置插件 `plume.ask-user`：

- agent 遇到自己答不了的问题（澄清意图、在几条路里拿主意）时停下来问人，问题卡压在输入框正上方。
- 选项可带一行说明和「推荐」标记；可单选或多选，可以在「其他」里自己写，也可以跳过。跳过时若 agent 指定了默认项则采用默认项（卡上写「跳过将采用：…」），否则只继续做不依赖这个答案的事。
- 键盘：1–9 选第几项，0 到「其他」，Esc 跳过，回车确认。
- 完全访问也不替人回答。等 30 分钟，卡上有倒计时；到时按没有答案收场，agent 会在回复里说明。
- 回答在插件里再核对一遍，不在选项里又不许自填、单选交了多个的不收。
- 转录里写「征询 …」。
