# 多会话协作

一个任务跨多个会话完成的几种方式：子智能体、侧边聊天、会话之间互发消息、建议新会话、代码审阅和定时任务；以及插件代管的会话（把一个会话接到 Plume 之外）。

## 子智能体

内置插件 `plume.subagents`（随应用提供）：

### 派发与控制

- `task` 工具接收描述、提示词和可选种类，立即返回子智能体 ID；主 agent 继续独立工作，结果自动送回（忙时在步骤边界送入，闲时唤起一轮），无需轮询。
- 每个父会话最多同时跑 4 个，多的排队，在面板里可见、可在开跑前停止。
- `task` 的 `resume` 在同一个子会话里续跑，保留历史、种类、工具限制和模型；运行中的不能重复续跑。
- `stop_subagent` 只停一个任务（转录里写「停止子任务」）。主会话正常结束不影响后台任务；明确停止主会话时，运行中和排队中的子任务全部停止、不再送回。删除会话也会取消。
- 子智能体不能再派子智能体；它的风险操作走产品审批卡，卡片标明来源。一次运行结束时，它自己起的后台任务被强制停止。
- 只有侧栏里的顶层会话能派：插件的子会话、独立会话（比如 SSH 的运维助手）下面建不了子会话，`task`、`stop_subagent` 和子智能体名单都不给模型，调到了也拒绝并说明原因。

### 交付

- 定义里写了 `output`（JSON Schema）的种类做完调用 `yield` 交结构化结果；不合格的退回并点名问题，连续三次仍不合格时 `schemaMode: permissive`（默认）带警告照收、`strict` 不收。交了空壳不算结束。
- 每 60 步（定义的 `maxTurns` 可改）一个检查点：待办清单比上个检查点多勾了就接着跑；一项没勾允许一段，连续两段没勾就停下；没写清单的先让它列一次；清单勾完还在忙也停下。停下时要求交一份交接（做完了什么、还剩什么、下一步）。一次运行最多 200 步。
- 交回主会话的正文包在 `<subagent_result …>` 里；停在检查点、原地打转、服务出错时标 `incomplete`，正文第一句说明原因。
- 主 agent 用 `read agent://<id>` 重读结果，`agent://<id>/<字段路径>` 取单个字段，`agent://` 列出本会话派出的全部子智能体。
- 续跑时上一段交的东西清掉。

### 界面

- 对话里的派发是一张卡片：带表情头像（悬停时眼睛跟着指针）、描述、`@agent`、「已完成 · 运行了 … · N 次调用」和打开按钮。结果回来时一行「消息来自 @agent · 描述 ›」。
- 输入框上方只显示还在运行或排队的任务。新一批任务派出时自动打开「子 Agent」面板（⌥⌘U，Windows 上 Ctrl+Alt+U）；手动关掉后不会反复打开。
- 面板：顶部头像叠放切换任务，显示状态、耗时、工具调用数、重连和等待批准；左侧可折叠的来源任务卡；最终报告单独显示、可复制；结构化回报按结构画（结论在前、发现按严重度排），没跑完的标「未完成的回报」。
- 运行中的操控框支持文字和附件插话，不打断当前工具；结束后保留禁用的输入框。输入框右下显示只读的模型、思考档位和上下文用量。
- 未完成的有「接着跑」，上下文已删时可「重新派发」；按钮只在主输入框准备草稿，人发送后才调用模型。

### 种类

内置八种：`general`（默认，通用研究与修改）、`explore`（只读搜索定位）、`review`（找缺陷与风险）、`verify`（执行一项检查并报告）、`plan`（只读规划）、`plan-review`（只读核实实施计划能否照做）、`simple`（大量机械改动）、`reason`（先想清楚再动手的难题）。每种都有自己的 `todo_write` 和 `yield`。

### 设置 › 智能体

- 顶上选层级（个人或某个项目）、条数和搜索；「已安装」是这一层自己写的定义，「内置智能体」是内置种类。每行显示头像、名字、工具数、用途，右边是模型、思考档位和开关；悬停有复制、删除（改过的内置是「恢复内置」）。
- 编辑器：头像（挑形状和颜色，骰子随机）、名字、范围、用途、指令、允许的工具；「高级」只读列出 `model`、`output`、`schemaMode`。未保存的改动关窗口也留着，取消时先问。
- 定义文件是带 frontmatter 的 Markdown，在 `~/.plume/agents/` 和 `<项目>/.plume/agents/`；同名时项目盖个人、个人盖内置。改内置的存成个人一份；删除移进废纸篓（Windows 上是回收站）。
- 模型不选时依次看定义的 `model`、跟随主会话。关掉开关的种类不进目录、派不出去；全部关掉时 agent 拿不到 `task` 工具。设置只影响新派发，已派出的保持派发时的指令、工具和模型。
- 「会话」一组里还可以选：智能标题模型、侧边聊天默认模型、记忆整理模型、会话摘要模型（装了对应插件时），以及默认生图模型（在组的最后）。

## 侧边聊天

内置插件 `plume.side-chat`（随应用提供）：

- 在对话旁边另开一段聊天：问主会话在做什么、为什么、某段输出什么意思，或顺手做件小事；主对话里不留痕迹，也不打断它正在跑的一轮。
- 「侧边聊天」面板（⌥⌘S，Windows 上 Ctrl+Alt+S）一个标签一段，可以开多个，标签名是它的标题；重启后恢复标签，弹出独立窗口后接回同一段记录。关掉标签即删除那段，说过话的先确认（可勾「不再询问」）。主会话删除时一起删除。
- 每问一句都附上主会话上次之后的新内容（12000 字预算）；更早的用 `read_main_chat` 自己翻。
- 能读文件、搜代码、改一处、跑命令、查网页；会改动的照常弹审批卡（压在主输入框上方）。只能编辑重问最后一句。
- 模型跟随主会话；输入框右下有上下文用量、模型和思考档位，模型菜单最前面是「跟随主会话」。新的侧边聊天用设置 › 智能体 › 会话的「侧边聊天默认模型」。第一句发出前也能先选模型和思考档位，发第一句时照选的开这段侧边聊天；上下文用量等第一句发出后才显示。
- **交出去**：`dispatch_task`——人说了「交给主会话」时直接排进主会话的队列（闲着当场开跑，消息标「来自侧边聊天」）；没说时画一张卡，人选交给主会话、开新会话（开在主会话的项目里）或就在这里做。交过去的活照常走主会话审批，不算新授权。
- **回执条**（侧边聊天插件画，状态由本体给）：画在侧边聊天转录和输入框之间，列出最近三件已收场的和排着、在跑的任务；悬停出现立即执行、撤回（那句话回到侧边聊天输入框）、重试或继续、移除。主会话停下时在跑的那件记为随主会话停下、可继续，排着的照旧排着。回执只在内存里，重开应用后只剩还排着的。
- **控制主会话**：`control_main` 当场暂停、继续、查状态；人明确取消旧目标时停下并作废旧的待办清单。主会话闲着时暂停不碰它挂着的开发服务器、监视、定时唤醒，侧边聊天也不替人停，只告诉人去主会话环境卡片里逐项停或点「全部停止」。
- 侧边聊天改过的文件，主会话下一问后面附一句 `<side-chat-changes>` 提醒重读，只说一次（只列净变化）。
- `/btw 问题`：在主输入框里另开一段侧边聊天问这句话，面板跟着打开；只敲 `/btw` 只打开面板。
- 主会话排队消息的「更多 › 在侧边聊天中打开」：这句话连同附件拿到面板里最早那段侧边聊天去问，没有就新开一格。
- 主会话里划选文字「在侧边聊天中提问」：引文作为带来源的签追加到侧边聊天输入框，复用当前可见的那段或新开一格，保留已有草稿和附件，不自动发送。

## 会话互通

插件 `plume.sessions`（从插件市场安装）：

- **看得见谁**：侧栏里的会话，与当前会话同项目、目录相同或互相包含、或互为开出来源的。子 Agent、侧边聊天不算，也用不了这些工具。
- **从别的会话开出来的**（计划交给新会话执行、建议新会话开出来的）：来源还在侧栏里时，系统提示词多一段，告诉模型它的来源 `[ref]`，拿不准来源里定下的事先 `read_session` 读、读不到再 `ask_session` 问。
- `list_sessions`：列出看得见的会话，每行地址 `名字 [ref]`（ref 是 id 前六位，改名后仍认得）、忙闲、清单正在做哪一步。
- `read_session`：读对方此刻的完整记录（可翻页，每页 12000 字，可按关键字找），不打断对方、不花对方的钱。
- `ask_session`：问对方只有它答得上的事或请它帮忙，当场返回；对方闲着就为这封信开一轮，忙着在两步之间读到，用 `reply_session` 回，答复送回来并叫起这边。
- `reply_session`：回答问过来的事；要花时间的先回一句打算，做完再回结果。
- `notify_session`：告诉对方一件改变它下一步的事，不要答复。
- **对方没回**（本体兜底，任何插件经寄信问出去的请求都一样）：读到却没回，那一轮收场时（完成、被人停下、出错都算）取它读到以后最后说的话代答（最多 4000 字，没做完就收场的注明怎么收场的），标「没正面回答」；读到之前被人停下、或送达被钩子拦下代答「没读到」；对方被删（读没读到都算）代答「关了」。对方回过的不再代答，答复不会到两次。
- **对话里**：来信画成一行「来自 …」「… 的答复」，点开读全文、箭头跳到对方。来信不是人的话，不算对任何操作的授权。
- **防打转**：一封最多两万字；三十秒内一字不差的不重发；同一对之间发太快的拦下（令牌桶）；一条往来链最多经手 28 次、同一会话最多 10 次，人一开口重新计数；每对最多 8 封未答。
- 人停下一个会话时，未读的请求丢掉（问的那边收到「没读到」）；通知和答复留着、不叫醒它，下次开口时接在那句后面。

## 建议新会话

内置插件 `plume.spawn-session`：

- **`spawn_session`**：模型看到一件值得做但不该塞进这次改动的事（死代码、过时文档、缺测试、顺手发现的安全问题）时，在对话里放一张建议卡片，写好标题、理由和新会话的第一句话。当场返回，模型接着做手上的事。
- **卡片**：参数还在写时是一行「建议新会话 · 标题」；写完是整张卡片：标题、理由、收起按钮，下面一排照输入框的排法——左边工作树开关（仅 Git 项目）和交回开关，两个都只有图标、开着时染强调色，右边模型、思考档位和「开始」。放不下时右边那组整组换行。
- **模型和思考档位**：和输入框右下角那两枚同一个样子、同一套菜单；一开始是默认模型和默认推理强度，不动就按默认开，改了新会话就用改的。
- **开始**：在这个对话的项目里（不在项目里时是它的目录）开新会话，叫建议的标题，发出写好的第一句；侧栏里挂在原对话下面。卡片缩成一行「新会话 · 标题」，在跑时扫光、没跑完时标红，点了过去。
- **工作树**：开着时新会话在自己的 Git 工作树和分支里跑；模型说明这件事会和别的会话并行改同一个仓库时默认打开。
- **收起**：卡片缩成一行「建议了新会话 · 标题 · 已收起」，只记在本机。
- **交回这里**：开着时，新会话跑完第一轮、它派出的子 Agent 和一次性的后台命令也都回来（开着的开发服务器、监视和没到点的唤醒不等）后，把最后那段回复送回原对话（一行「来自新会话 · 标题」）并叫起原对话。只交第一轮；被人停下的不交，出错、跑到上限的标「没跑完」照样交；第一轮没跑完就退出应用的不再交。
- **环境卡片**：「建议的新会话」一节列出还没决定的建议（只展示，点了滚回对话里那张卡片去选模型、开始）和已开始的会话；有未决定的建议时，标题栏的环境开关上挂圆点，说明写「N 条建议的新会话等你决定」。
- **`archive_session`**：人说「做完就归档」时，模型写完最后的回复后调用它，这一轮以完成收场后归档、界面离开它；停下、出错、卡住收场的不归档。可从设置 › 已归档的聊天找回。
- 子 Agent 和侧边聊天里没有这两个工具。

## 代码审阅

插件 `plume.review`（从插件市场安装）：

- **`/review [目标] [--effort low|medium|high] [--comment]`**：目标不写是未提交的本地改动；数字、`#123` 或 PR 链接是那个 PR（需装好并登录 `gh`）；其余当文件路径。力度默认：本地改动和文件 medium，PR high。`--comment` 把报告评论到 PR 上（发前会问）。
- 原对话填一份交接单（背景、人的决定和原话、实现、改动的文件、不做的、没验证的、重点），调用 `review_session` 在同一项目里开一个「审阅 · …」会话，这一轮停下。人说过的话、批准过的计划由插件从记录里原样附上。原对话在工作树里时审阅会话也开在那里。
- 审阅会话按力度派子智能体（low 不派；medium 三到四个 `review`；high 四个一批，加 `verify` 跑检查、逐条复核），出报告，每条标 CONFIRMED 或 PLAUSIBLE。
- 审阅会话和它派的子智能体写不了文件，直到它用 `ask_session` 问原对话修哪几条、原对话答复；之后只修点名的几条，修完再跑检查；全程不提交。
- 审阅会话真闲下来后把报告交回原对话（一行「来自新会话」），原对话几行说明发现了什么、修了什么、留下了什么。人按停的不交回。
- 对话里那一行「审阅会话 · 审什么」，在跑时扫光，点了打开审阅会话。
- 没装子智能体插件时各力度都按 low 自己审并在报告里说明；没装会话互通时不问、不修，发现都列在「Awaiting a decision」下面。在子智能体、侧边聊天里敲 `/review` 就地审完整条流程。

## 定时任务

插件 `plume.scheduled`（从插件市场安装）：

- 侧栏的「定时任务」页面，一张卡片一个任务：名字、提示词、时间、开关直接在卡片上改，改完即存。
- 两种时间：每天固定时刻，或每隔多少分钟（最快一分钟）。开着的任务写下次运行时间。
- 新任务记下建它时打开着的会话所在的项目（没有项目时是会话的工作目录；没打开会话时是空白页选的项目或目录），每次运行都开在那里。
- 应用开着时每分钟检查一次（启动 5 秒后先查一次），到点开一个新会话、把提示词作为第一句发出。上一次还没真正闲下来（第一轮、它派出的子 Agent、一次性的后台命令都结束；开着的开发服务器、监视和约好的唤醒不等）时不叠跑，结束后只补一次。关着时错过的，下次打开后补跑一次。
- 卡片上的 ▶「立即运行一次」不看时间和开关，停用的任务也会跑。
- 卡片显示正在执行、等待你的批准、「打开上次会话」、上次失败的原因（没开出会话，或第一轮出错、原地打转、用满步数；人按停不算）。
- 没人看见的失败在输入框上方提示（「查看」跳到那张卡片、「知道了」），侧栏「定时任务」那一行挂数目，通知菜单里也列出；打开这一页就算看过。
- 任务存在插件数据目录的 `tasks.json`。

## 插件代管的会话

本体提供的能力（`launch({ steward: true })`、`ctx.sessions.post` / `respond` / `answer`），给要把会话接到 Plume 之外的插件用（比如外面的人经 IM 发消息、在 IM 里答审批）。现在只有测试插件「代管探针」（`packages/testing/steward-probe`，不随应用发）在用。

- **开出来**：插件开一个新会话并代管它。它照旧是人的会话：进侧栏，人能接着聊；标题栏标题旁和侧栏悬停卡片写「由 X 代管」。
- **转话**：插件把外面的话转进来，和人在输入框里发的排同一条队：闲着当场开一轮，忙着排着，不打断正在跑的一轮。气泡上标「X 转来」；模型读到的前面有一句说明：这是插件从 Plume 之外转来的，不是人在输入框里打的，发送者 Plume 没有核实，权限和审批照这个会话的设置。
- **代答**：会话里弹出的审批卡（包括提权）、提问卡、计划卡、表单，插件都能替人答（允许这一次、拒绝、交回答案），「以后不再问」除外。挂在这个会话下面的子会话（模型派的子智能体、人开的侧边聊天）弹的卡也一样，人在桌面上看到的还是压在这个会话输入框上方、写明哪个子会话在问的那张；插件只能往这个会话自己里转话，不能往子会话里转。桌面上的卡照样显示，人和插件谁先答算谁的；插件答的那次调用底下写「由 X 代答」，模型读到的结果里也写明是插件转达的。答的人是不是该答的人由插件确认。
- **权限**：照这个会话的设置，不因话是插件转来的而变：完全访问下转来的那一轮也是完全访问。
- **停止代管**：会话菜单（侧栏右键、标题栏）里的「停止代管」随时收回：之后插件再转话、答卡（包括子会话的卡）都被拒，它转来还排着的话一起拿掉，正在跑的那一轮不停；那时已经弹着的卡之后只能人答。插件只能动自己开出、还在代管的会话，碰不到人已有的会话和别的插件代管的会话；分叉出来的会话不带代管。
