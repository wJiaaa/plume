# Agent 核心

这部分是 agent 每一轮怎么跑：组上下文、调模型、执行工具、收尾续写，以及系统提示词、上下文压缩、重复检测和智能标题。

## 一轮的流程

- 用户消息先经插件检查（可能被钩子等插件拦下，被拦时这条不写进会话，原因弹成提示条），然后写进会话。
- 组上下文：系统提示词 + 历史消息 + 工具表；必要时先压缩。
- 调模型，回复流式显示并边收边写进会话。
- 执行工具调用：相邻的只读调用同时跑，会改动的单独跑，结果按调用顺序写回；需要审批的先问。
- 有工具结果就继续下一步；一轮最多 200 步。
- 停止时，没执行的调用补一条「没有执行」的结果。

## 收尾与续写

- 回复撞上输出上限时以系统身份补一句「接着写」，连续三次仍撞上就停下提示；回复没有正文时催一句，三次后以出错结束。
- 工具参数撞上输出上限时判失败、让模型拆小，连续四次以出错停下。
- 多个工具同时丢了必填参数时，先补纠正结果而不执行，连续三步后以出错停止。
- 连续 20 个工具请求没有向人汇报进度时提醒一次当前进度（不强制停止）；装了待办清单时由清单插件给出自己的汇报提醒。
- 还有子智能体没回来时，主 agent 不先写最终结论：每 4 次带工具的请求提醒一次还在等谁；回复为空时改催「在等谁」。
- 停下时的提示走提示条。

## 重复调用检测

- 同一个工具、同样的参数、同样的结果，第 3 次起发给模型的结果换成「这是第 N 次」（会话和卡片里仍是原文），那一步收尾时提醒换思路；第 10 次以「卡住」结束这一轮并弹提示条。
- 人发新消息时计数清零，「继续」不清零；成功的 edit、write 后清零。
- 翻页查同一个问题第 12 次、切图测距第 5 次各提醒一次，不据此停止。
- 结果比对包含图片内容；丢了参数的工具步不计入。
- 计数只在内存里，重启后从头算。

## 系统提示词

内置插件 `plume.prompt`，随应用提供、不能停用：

- 按段组成：身份、做事准则、边界、环境（平台、shell、是否 git 仓库、模型）、设置 › 个性化里的语气和全局指令、项目指令、工作目录、会话临时目录（只为这次回答写的文件放这里，随会话删除）、项目的其他源文件夹。
- **项目指令**：从工作目录向上到仓库根，每层按 `PLUME.md` → `AGENTS.md` → `CLAUDE.md` → `.agent/AGENTS.md` → `.agents/AGENTS.md` 取第一份非空文件；不在 git 仓库里只读当前目录。最多 10 层、每份 100 KiB。
- 环境段按权限模式点名命令实际使用的 shell，有 bash 工具时写明 PowerShell / Git Bash 的写法；计划模式下按只读那一档点名。
- 其他插件按段名加段：记忆、技能目录、MCP 延迟加载的工具目录、子智能体名单（含最多同时跑几个）、资源地址清单、计划模式规则、下一步建议、原生界面块说明等。
- **会话内冻结**：系统提示词在会话第一次请求时定下，之后原样复用，以命中服务商的前缀缓存。中途变化的段（项目指令、技能、子智能体名单等）作为一条增量消息接在下一轮开头；压缩后、或撤回到第一条消息时按磁盘现状重新冻结。冻结的那份存在插件数据目录，重开应用仍是同一份；转录和导出里看不到增量消息。
- **日期**：不进系统提示词，跟在每个新日期的第一条用户消息后面。
- **插话和打断**：中途插进来或打断了一轮的消息，发给模型时前后各加一句说明。

## 上下文压缩

内置插件 `plume.compaction`，随应用提供、不能停用：

- **剪过大的结果**：一条工具结果第一次发出前超过约 32k 字的剪成头尾，中间换成标记和 `artifact://` 地址，模型可以用 read 读回原文。
- **触发**：请求到上下文窗口的 90% 时压（小窗口另给摘要留位；有分档价格的模型按不低于 128k 的最低一条分档线算）；服务商报超长、人敲 `/compact` 时不论多满都压。一轮干净收尾、缓存还热时也会在空闲时压一次，人一开口就让位。
- **先剪枝**：清空「没搜到」「空目录」这类无内容结果；早被后面的读、改覆盖的结果，以及超过约 8k 字且模型已看过的结果剪成头尾。剪完低于触发线一成就不写摘要。
- **保留尾部**：从后往前原样保留，最多约窗口的 12%，至少 4 条；对话不超过 6 条时不压。
- **摘要**：缓存还热（同模型、离上次请求不到缓存时长，默认 4.5 分钟）时从主请求分叉写摘要以命中缓存；否则单独请求，太长时分段写（最多四遍）；都失败时本地机械整理；仍放不下就按条丢弃最老的几轮。摘要固定分为目标、约束、进度、决定、下一步、关键上下文几节，第二次起在上一份基础上更新。花销记在会话名下。
- **摘要头**：带上最新那条请求的原话和更早的请求、批准的计划、读过和改过的文件，以及一句「原文能用 `recall` 找回」。
- **`recall` 工具**：在这个会话的全部原文里按词搜索（每个词都要出现、不分大小写），最新的在前，`offset` 翻页。
- **`/compact [希望保留的内容]`**：立即压缩，补充的话进摘要指令；对话在跑时不压。输入框里也可以用 `@compact`。
- 会话里的消息一条不删，界面上仍能看到完整对话；摘要、边界、剪枝结果另存，重开应用照样发送。
- 转录里的压缩行：自动压缩的进行中、等重试、本地整理、失败、被中断；压完是一条分隔线；人敲的 `/compact` 是一只气泡加进度和结果。
- `artifact://` 原文只在内存里（每个会话 30 份）：重开应用后剪过的结果照样剪着发，但地址读不回原文。
- 服务商因内容拒收时，把过大的工具结果剪成一行再发一次；报超长时强制压缩一次再发；恢复成功的话失败那次不写进会话。

## 智能标题

内置插件 `plume.title`：

- 会话发出第一条消息时，在后台用模型把它概括成一句 6–18 字的标题，语言跟消息一致；问题写成「问的是什么事」，不回答它。不拖慢回复。
- 消息去掉多余空白后不超过 12 个字时直接用原文，不调模型。输入最多取前 4000 字，回复上限 60 token。
- 没配模型、15 秒内没回来、出错、结果不像标题时，保留默认取的消息开头。
- 人改过名的会话不覆盖；子会话、系统消息不处理。
- 开关在设置 › 常规的「智能标题总结」（默认开）；模型在设置 › 智能体 › 会话的「智能标题模型」里选，不选用会话自己的模型；选的模型没了就不再起标题。用量记在该会话名下。
