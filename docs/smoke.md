# 冒烟：怎么跑、各段验什么

## 怎么跑

`pnpm smoke` 构建一次，把冒烟分成二十来段，每段起一个真实 Electron 并行跑，最后列出每段过没过，没过的给出只重跑它们的命令。输出 `PLUME_SMOKE {...}`。

挑段：

- `PLUME_SMOKE_ONLY=a,b`：只跑这几段。段名就是 `apps/desktop/src/main/smoke.ts` 里 `PLUME_SMOKE_ONLY === "…"` 的那些分支，写错了会列出能跑的。
- `PLUME_SMOKE_ONLY=changed`：按改动挑段，相对 `PLUME_SMOKE_BASE`（缺省 HEAD，即还没提交的改动），先列出挑了哪几段、为什么。挑法见 `scripts/smoke-changed.mjs`。

并行和隔离：

- 同时跑 4 段，`PLUME_SMOKE_JOBS` 可改。环境卡片那段大半在等定时器，不占名额；读写系统剪贴板的几段错开。
- 每段一份自己的数据目录，互不影响。
- 多个会话可以同时跑，不用等别人跑完：构建排队、一次一个（几秒，锁是 `.smoke/.build.lock`，持有的进程没了自动失效）；构建完把产物快照到这次运行的 `app/` 下、从快照启动，别的会话再构建也动不到它，跑完删掉快照。

产物：

- 截图和数据放在 `.smoke/<时间戳>/<段名>/`，只跑一段时直接放在 `.smoke/<时间戳>/`；只跑一段时也可设 `PLUME_SMOKE_OUT=<截图路径>` 自己指定。
- 每段的日志是其中的 `smoke.log`。
- 过了的段删掉装进去的插件和数据目录；`.smoke/` 下只留最近 10 次运行。

市场插件：

- 各段要用的市场插件缺省从线上市场装，要联网。
- 改了插件接口、线上那批插件跟不上时，用 `pnpm market:local` 打一份本地市场，再 `PLUME_SMOKE_MARKET=<市场目录> pnpm smoke`：冒烟在 127.0.0.1 上起静态服务、从那里装，跑完关掉。地址经 `PLUME_SMOKE_MARKET_URL` 告诉应用，只在冒烟时认，`pnpm dev` 和装好的应用不认。

Windows 上也能跑：`plume-plugin` 经 `cmd.exe` 起，终端和钩子那几步用 PowerShell 的写法，超时时连进程树一起结束（`apps/desktop/scripts/stop-process.mjs`）。

### 本地市场：`pnpm market:local [<插件仓库>] [--out <目录>] [-- <命令>...]`

- 拿这个工作树的插件 SDK 构建插件仓库，打出只含本机平台的市场目录（缺省 `.smoke/market`）。
- 插件仓库的位置：直接给路径，或设 `PLUME_PLUGINS_DIR=<插件仓库>/plugins`（缺省取它的上一级）。`pnpm check` 不碰插件仓库。
- 带 `-- <命令>` 时不打市场，换上本地 SDK 在插件仓库里跑这条命令（如 `-- pnpm check`）。
- 做法：在插件仓库的 `pnpm-workspace.yaml` 临时加 `overrides`，指向 `npm pack` 出来的 SDK，再重装依赖；不管成没成，最后都还原 `pnpm-workspace.yaml`、`pnpm-lock.yaml` 并按原锁文件重装。所以这两个文件动手前得是干净的。
- 只按路径调插件仓库的命令，不引用它的文件（`scripts/local-market.mjs`）。

## 主窗口启动页

`boot-screen` 在独立的真实 Electron 段里，用应用自身的外观设置分别切到浅色和深色后重载主窗口。不拦截后台连接，在启动页正常显示期间截取画面，其他段不增加等待。

断言启动页图片解码成功、原始 PNG 的 SHA-256 和 768 × 768 像素尺寸未变，加载条宽度为 128 像素，启动标志淡入可见；等待启动页自然卸载，再确认正常主界面的输入框可以聚焦。换原图时同步更新 `smoke-boot-screen.ts` 中的图片摘要及尺寸断言。

运行单段（命令会构建）：

```sh
PLUME_SMOKE_ONLY=boot-screen pnpm smoke
```

单段产物在 `.smoke/<时间戳>/`：`smoke-boot-light.png`、`smoke-boot-dark.png` 是启动页，`smoke-boot-ready-light.png`、`smoke-boot-ready-dark.png` 是进入并操作后的主界面。整轮运行时产物在对应时间戳下的 `boot-screen/` 子目录；本段失败时沿用公共冒烟流程保存 `smoke.png`。本段覆盖重载时的真实启动界面与退出，不用于测量冷启动性能或启动页实际停留时长。

## 面板开合时的转录连续排版

`panel-transcript` 用真实 Electron 的标题栏面板开关（与主流程相同的 `[data-panel-toggle] button`），不改 DOM 样式、不注入会话记录、不调用真实模型、不安装市场插件。固定窗口 1200 × 800、缩放 100%、启用动画，分别构造一轮短会话、24 轮长会话和含 360 段正文及 240 行 TypeScript 的超长单条回复。长场景同时覆盖贴底和向上阅读，超长回复的阅读位置落在代码块开头，额外校验代码块不撑破正文。每种位置连续打开、收起各三次。第 0 次保留为首次测量，第 1、2 次可看热态重复性。

每个 `requestAnimationFrame` 记录对话卡片、转录视口、回复容器与段落宽度、按卡片实时宽度推算的正文目标宽度、滚动位置、距底距离、内容高度和可见段落锚点。目标宽度不是从可能被冻结的正文或滚动面宽度反推，因此能抓到「卡片在动、正文保持旧宽度」的情况。校验至少三个动画中间帧、宽度误差不超过 3px、卡片到位后正文不再跳宽、正文不重挂、不多出底部空白；贴底后距底不超过 3px，阅读历史时不被带回最新，锚点漂移不超过 64px。帧时间不设机器相关的通过门槛。

运行单段（命令会构建；请由需要执行验证的人运行）：

```sh
PLUME_SMOKE_ONLY=panel-transcript PLUME_SMOKE_OUT="$PWD/.smoke/panel-fixed/smoke.png" pnpm smoke
```

原版与修复版对照必须使用**完全相同的这份冒烟代码**：在原版工作树也带上 `smoke-panel-transcript.ts` 和 `smoke.ts` 中对应的 import、分支，但不带渲染器修复。分别在两个工作树运行上面的命令，将输出目录改成 `panel-original` 和 `panel-fixed`。不要并发跑两份，使用同一机器、显示器、系统深浅色、窗口可见状态和电源设置，避免其他冒烟或重负载；推荐交替各跑三轮。脚本会关闭系统的减少动态效果模拟并固定窗口、缩放，测试内容、轮数和开关路径一致。原版出现断言失败是有效的回归证据，不应为跑完原版而关掉断言；所有场景采集完才统一判定宽度与滚动断言。

输出目录里的 `panel-transcript.json` 包含 `conditions`、汇总 `report`、失败原因 `failures` 和原始逐帧 `samples`；终端同时打印 `PLUME_PANEL_TRANSCRIPT`。先看 `failures`，再按 `name`、`position`、`direction`、`repeat` 对齐两版记录：`widthError` 是逐帧最大宽度误差，`tailJump` 是卡片到位后正文剩余的宽度变化，`anchorDrift` 是阅读锚点最大位移，`finalLag` 是结束时距底距离。`p95FrameMs`、`maxFrameMs` 和 `over32Ms` 只统计卡片开始移动前一帧到首次到位的动画区间，不把等待开关和结束后的静止帧混进去，用来比较同条件下的卡顿；第 0 次与第 1、2 次分开比较，不以一次最大值宣称性能改善。原始帧的 `t` 是渲染器单调时钟，相邻差值就是帧间隔；把 `main`、`expected`、`body`、`paragraph` 按时间叠在一起，正文曲线应跟随目标曲线，不能横着不动后在结尾竖跳。

每种场景和滚动位置还留有结束截图；运行异常时有 `panel-transcript-error.txt` 和失败截图。截图只能确认最终外观，动画是否连续以原始帧和断言为准。本段不覆盖流式生成和减少动态效果模式。

## 其余各段

`desktop-compat` 也检查欢迎页：在面板区收起时放大、缩回真实窗口，收到 `resize` 当下就量工作区和输入框，确认单屏已铺满、输入框仍居中，而不是等布局稳定后才量。这条冒烟只检查页面布局；要核对原生缩放动画的窗框和页面是否同帧，需要看系统录屏。

macOS 27 的标题栏缩放另用系统录屏验：系统双击动作为放大、且未开启「减少动态效果」时，在主窗口的新会话双击顶行空白处放大、还原，连续两轮。录屏里窗框应经过连续的中间尺寸，不能停在起点直接跳到终点；同时逐帧核对输入框相对当帧对话区居中、未裁切，还原后位置和大小不变。这两项分开判断。不能用 `window.maximize()` 或在页面派发 `dblclick` 代替原生双击。

`screenshot-lifetime` 在真实 Electron 里经主窗口注册截屏快捷键：还有一个能用的组合时保留原浮层，撤销最后一个时销毁，重新注册可再次预热。只验证预热和回收，不触发真实截屏交互，也不要求授予屏幕录制权限。

`transcript-scroll` 还检查欢迎页的滚动区：没有溢出时不挂渐隐遮罩；从顶部滚到中间和底部时，两端深度跟随滚动位置；内容重新装进一屏后撤下遮罩。末尾用假模型流式输出逐渐变宽的代码（含普通多行代码与单行可执行 shell 命令）与表格，验证宽度经过中间值、写完回到自然排版、文本完整、代码块默认自动换行且不显示语言名、按钮不单占一行、单行 shell 与执行/复制按钮同行居中、窄窗不撑破正文及表格换行开关；开启「减少动态效果」后再跑一次，确认不播放宽度动画。逐帧尺寸在 `markdown-width-animated.json`、`markdown-width-reduced.json`，浅深截图是 `smoke-markdown-width-light.png`、`smoke-markdown-width-dark.png`。再构造含 20 组代码块与表格的长回复，切走再切回，确认屏外块跳过布局、占位和完整布局的高度相同；缩窄窗口后重新核对高度，并滚到之前跳过的表格，确认横向滑块恢复。`conversations` 另逐帧验证已选项目首次发送时分支签连续可见；从有目录的会话打开无项目空白页不算同一工作区的交接。

`markdown-images` 验证无需图片插件即可显示本机图片（包括指向会话目录外文件的软链）、损坏和缺失图片保留链接、回复里的远程引用不自动请求、点正文图片打开看图器并在同一条回复的图之间翻页；同时覆盖 Markdown 文档的相对图片与 HTTPS 图片、行内徽章尺寸、同名文件刷新、历史图片恢复、流式占位及窄窗口。

`pnpm smoke` 怎么跑、输出在哪见上面「怎么跑」和 `scripts/smoke.mjs` 的文件头。这里记各段覆盖了什么，加段、改了一段的覆盖面时同步。
