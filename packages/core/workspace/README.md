# 工作区

替模型读写这台机器时本体守的线、改了什么的记录，和在宿主上安全地读仓库（`@plume/workspace`）。本体的一部分，插件换不掉：卡片怎么画、人拒绝了怎么告诉模型、这次调用改了哪些文件记在结果上、撤回时连文件退在 `@plume/agent`（`src/run-files.ts`），插件的工具经 `ToolRun.files` 读写、跑命令时带 `recordChanges` 请本体观测，插件经 `ctx.resources` 登记资源地址、经 `ctx.workspace.files` 列项目文件、经 `ctx.changes` 汇总和撤销改动。这个包只认「路径、目录、数据目录、会话 id」，不认循环、不认插件；给人看的话由调用方按界面语言给（`ChangeWords`）。

## 它做了什么

- **读边界**（`read-access.ts`）：工作区、同一个项目的其他源码目录、各会话的临时目录、系统临时目录和工具链的系统目录、人拖进来的文件不问；密钥文件在哪都问、只批这一个；别处按所在的项目问（往上找到仓库根，家目录和根目录不当批准范围）。判定前顺着符号链接走到真实位置；不存在的普通路径不问。一行命令写明要读的路径照 shell 的语法拆出来按同一个边界判（重定向的目标、heredoc 的正文、shell 会改写的词不算）。
- **写边界**（`paths.ts`）：模型要写的路径照读的那几种写法解析；Plume 自己的目录（`~/.plume` 和数据目录）不写，工作区本身在那下面、同一脉会话的临时目录除外；看着在工作区或临时目录里、链接到外面的拒绝（审批卡上只写着那个名字）。工作区外照样能写，要不要问人归工具。
- **写文件**（`text-file.ts`）：同一个文件（按真实路径和 inode，硬链接、别名算一个）的几次写排队；写之前再核一遍内容、权限、mtime 和 inode 没变，新文件用独占创建，不跟随链接；写下就记快照，快照存不下来时照实说文件已写下。
- **改动快照和撤销**（`change-store.ts`）：快照记在数据目录的 `changes/<会话 id 的 SHA-256>/<uuid>.json`（`0600`），只交出标识，不交原文。汇总按文件算首次写之前到末次写之后的净变化，改回原样的不列；撤销重新读快照，只撤连续的、当前身份和内容仍对得上的、项目内的普通文件，有一个不对就都不写，写到一半失败尽力退回、不覆盖后来的改动，新建的文件删掉。命令改的不自动撤销，说得出不能撤的是哪一类（命令、穿插、项目外、之后被改过）。删会话时删掉，之后迟到的记录不再落盘。
- **命令观测**（`command-changes.ts`）：命令起来之前、结束以后（连它留下的进程一起退出）各在隔离视图里问一次 git 工作区里改动着的文件，对比原文记下改了的；最多 200 个文件、单个 2 MiB、合计 16 MiB，二进制、像密钥的（`.env`、私钥、凭据）不读，只说没记全。
- **门闩**（`change-lock.ts`）：撤销和改动互斥，一个 agent 一把：撤销写回文件时不能写文件、不能起要观测的命令、不能开始新的一问；还有改动或正在送进会话的一问时不能开始撤销。
- **资源地址**（`resources/`）：`scheme://路径[:行-行]` 的路由，本体自己的 `scratch://`（会话的临时目录，唯一可写，软链出不去）、`artifact://`（被剪掉的大块原文，按会话在内存里）、`session://`（别的会话的转录）、`plugin://`（插件的 README 和目录里的文件）；插件登记的 scheme 只留读的几样。
- **在宿主上读仓库**（`host-git.ts`、`project-files.ts`）：沙箱里的命令写得到 `.git/config`，宿主上直接跑 git 会执行里面配的程序（`core.fsmonitor`、过滤器、钩子）。真实仓库上只跑 `rev-parse` 和 `config --list`；别的命令在数据目录下临时生成的 `GIT_DIR` 里跑：配置只留白名单里几个纯数据键，系统和全局配置关掉，没有钩子和远端，index、对象库指回真实仓库，跑完删掉。项目文件清单（git 认为该看的文件）、命令观测和本体文件面板找文件都经它。
