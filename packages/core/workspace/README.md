# 工作区

替模型读这台机器时本体守的线，和在宿主上安全地读仓库（`@plume/workspace`）。本体的一部分，插件换不掉：卡片怎么画、人拒绝了怎么告诉模型在 `@plume/agent`（`src/run-files.ts`），插件的工具经 `ToolRun.files` 读，插件经 `ctx.resources` 登记资源地址、经 `ctx.workspace.files` 列项目文件。这个包只认「路径、目录、数据目录」，不认会话、不认插件。

## 它做了什么

- **读边界**（`read-access.ts`）：工作区、同一个项目的其他源码目录、各会话的临时目录、系统临时目录和工具链的系统目录、人拖进来的文件不问；密钥文件在哪都问、只批这一个；别处按所在的项目问（往上找到仓库根，家目录和根目录不当批准范围）。判定前顺着符号链接走到真实位置；不存在的普通路径不问。一行命令写明要读的路径照 shell 的语法拆出来按同一个边界判（重定向的目标、heredoc 的正文、shell 会改写的词不算）。
- **资源地址**（`resources/`）：`scheme://路径[:行-行]` 的路由，本体自己的 `scratch://`（会话的临时目录，唯一可写，软链出不去）、`artifact://`（被剪掉的大块原文，按会话在内存里）、`session://`（别的会话的转录）、`plugin://`（插件的 README 和目录里的文件）；插件登记的 scheme 只留读的几样。
- **在宿主上读仓库**（`host-git.ts`、`project-files.ts`）：沙箱里的命令写得到 `.git/config`，宿主上直接跑 git 会执行里面配的程序（`core.fsmonitor`、过滤器、钩子）。真实仓库上只跑 `rev-parse` 和 `config --list`；别的命令在数据目录下临时生成的 `GIT_DIR` 里跑：配置只留白名单里几个纯数据键，系统和全局配置关掉，没有钩子和远端，index、对象库指回真实仓库，跑完删掉。项目文件清单（git 认为该看的文件）和本体文件面板找文件都经它。
