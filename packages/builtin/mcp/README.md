# MCP

接入 MCP（Model Context Protocol）服务，把它们的工具交给 Agent 用：搜索、数据库、浏览器、设计稿……

服务返回嵌入的 Word、Excel／ODS、PowerPoint 或 SQLite 文档时，工具结果下方会显示文件卡片，点击「预览」使用统一只读预览。每次结果最多 16 份、合计 64 MiB；快照保存在插件私有目录，按会话隔离，删除会话时清理。会话记录只保存文件引用，不塞入二进制；原来的文字和图片输出保留，资源链接不会自动下载。

## 它做了什么

- **工具**：每台开着的服务连上以后，它的工具以 `mcp__<名称>__<工具名>` 出现在 Agent 的工具表里。每次调用前弹审批卡问你，答「以后不再问」就记住这一个工具。
- **断了自己重连**：连着的服务半路断了，隔一会儿再连（从 0.5 秒起翻倍，最多 8 次），这期间工具还在，调用会等它一会儿。
- **工具多了按需搜索**：所有服务的工具加起来太多时，工具表里只留 `mcp_search` 和 `mcp_call`，系统提示词里列出有哪些服务和工具名，Agent 要用时先搜到用法再调。几乎每次都要用的服务可以设成「常驻」，它的工具一直直接给 Agent。
- **资源**：服务声明的资源（日志、文档、配置……）Agent 用 `read` 读：`mcp://` 列出连着的服务都有哪些，`mcp://<名称>/<资源>` 读其中一个，`<名称>` 和工具名里的那一段一样。读资源不问你，只读文字，图片这类二进制资源读不了。每个会话独立的服务读这个会话自己那一份。
- **prompt 进 `/` 菜单**：服务提供的 prompt 是一条命令 `/mcp:<服务>:<prompt> 参数`，发出去的是服务按参数填好的那段话。只有一个参数时整段都给它，否则写成 `名字=值` 或按顺序写。
- **服务中途要你填的表**：服务干到一半要你补几样东西（账号、要不要继续、选哪个）时，输入框上方弹出一张表。填好「提交」交给它；「拒绝提供」是明说不给；「取消」是先不决定，服务可能过会儿再问。表只由你答，「完全访问」和「以后不再问」都不替你填。几个会话同时在用同一台服务时说不清该问谁，就替你答「不给」。
- **太长的结果**：交给 Agent 的截掉中间，全文存进这个会话的临时目录，告诉 Agent 去哪读。
- **结果里的图**：200 KiB 以内的直接交给 Agent；再大的（5 MB 以内）不塞进请求，存进会话的临时目录，Agent 拿到一句说明和路径，要看时自己读；超过 5 MB 的只说一声。卡片上都画出来。音频只写一句说明。会话删掉时临时目录一起删。
- **「插件市场 › 连接器」**：每台服务（连接器）一张卡片，写着它连没连上、带来了几个工具（点开能看工具列表）；连不上时摊开原因和服务最后写到 stderr 的几行，可以重新连接。添加在弹窗里；改已有的点卡片上的调节按钮就地改（名字、命令、参数、变量、三个开关），焦点离开那一块就存。

## 两种服务

- **本地进程（stdio）**：填命令和参数，比如 `npx` 加 `-y @modelcontextprotocol/server-github`。进程用你登录 shell 的环境（`PATH` 里的 `npx`、`uvx` 都找得到），再加上这里填的环境变量。
- **远程 HTTP**：填地址，传输方式选 Streamable HTTP 或 SSE。要令牌的服务在请求头里填，比如 `Authorization` 写 `Bearer <令牌>`。

名字像密钥的环境变量和请求头（`…_TOKEN`、`…_KEY`、`Authorization` 这些）不会再显示原值，编辑时留空就是保留原来的。

## 空位和登录

- **`${NAME}` 空位**：命令、参数、环境变量、地址、请求头里都可以写 `${NAME}`（比如 `Authorization` 写 `Bearer ${LINEAR_TOKEN}`），连接时填上：先用卡片上填的值，再从登录 shell 的环境变量里找。都没有时卡片标「缺少密钥」，在卡片上填好、焦点离开就会启动。写成 `${NAME:-默认值}`（Claude 格式的同一种写法）是可选的：没值用默认值，不算缺；一个环境变量或请求头里的空位全落空时整条不发，可选的令牌不填就不带 `Authorization`。
- **OAuth**：远程服务的请求头里没写 `Authorization` 的，按 OAuth 处理。它要登录时卡片标「需要登录」，点「登录」在浏览器里授权，完成后自动连上；令牌过期了用刷新令牌换新的。令牌存在插件数据目录（每台一个文件，只有你能读，经内置插件「密钥加密」加密），不进界面。⋯ 菜单里可以退出登录。

## 每个会话独立

默认所有会话共用这台服务的同一个进程。打开「每个会话独立」后，每个会话第一次用到它时各起一个，会话删掉就关；适合把状态留在进程里的服务，比如操控浏览器、保持数据库连接的。

## 信任只读声明

服务器可以给工具标上「只读」。默认照样每次都问；对信得过的服务器打开「信任它的只读声明」后，在「帮我批准」模式下，它标为只读的工具不再逐次确认。标为会删除或覆盖数据的工具始终要确认。

## 用法

随应用发，不用安装。在「插件市场 › 连接器」里添加服务。

## Magpie 资源库分发的服务

在 Magpie 资源库里选 Plume 分发的 MCP 服务写在 `~/.plume/magpie/mcp.json`（Claude 格式的 `mcpServers`），这个插件启动时和自己的服务一起读，改了要重启 Plume。卡片上标着「由 Magpie 管理」：名称、开关、启动方式、变量和删除都锁住，在 Magpie 里改；连接状态、工具列表、重连和 OAuth 登录照常。它们不会被抄进 `servers.json`，在 Magpie 里撤回就没了，登录令牌在下次改 MCP 配置时清掉（删掉的服务也一样）。和自己的服务重名的不接，保留自己的那台。

## 插件带来的服务

插件目录里放一份 `.mcp.json`（同样是 Claude 格式的 `mcpServers`），插件开着时它的服务就出现在这里：「插件市场 › 连接器」里的条目就是只带这个文件的插件。插件装上、卸下、启用、停用时当场重读、连上或断开。卡片上写着「由插件 … 提供」：能开关，缺的 `${NAME}` 值在卡片上填，「启动方式与环境变量」里列出声明的每个空位（可选的也在），填过的能换、能清掉；名称、启动方式改不了，也不能删，要移除就卸载那个插件。人改过的开关和填的值记在 `servers.json` 的 `plugins` 里（像密钥的照样加密），插件停用、卸了再装还在。和已有的服务重名的不接，保留先来的那台。

## 现在还没有

服务要你去网页上完成的那种请求（URL 模式）。prompt 里的图片只写一句说明。

配置存在插件数据目录的 `servers.json`。名字像密钥的环境变量、请求头和填过的值经内置插件「密钥加密」（plume.secrets）加密后写进去，文件里是 `plume-sealed:v1:` 开头的一段；直接在文件里手写的明文照样能用，下次在设置页改配置时加密。加密用的钥匙丢了，这些值会显示成没填，重新填一遍就行。
