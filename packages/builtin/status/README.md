# 用量与状态

在输入框里、模型选择的左边放一个上下文用量的小圆环：扫一眼就知道窗口快不快满，不用翻消息、不用开设置页，就能判断该不该开个新对话。

## 它显示什么

- **圆环**：上一次请求把上下文窗口占了多少，悬停写「上下文占用 41%」。到 80% 变成红色：压缩在窗口真满之前就开始，提醒要早一些。
- **点开**：「上下文窗口 82.4k / 200.0k（41%）」、一条分段的进度条，下面是对话消息、工具、系统提示词各占多少和剩余空间；项目指令和记忆合成「记忆文件」一行，展开按文件列出各占多少（AGENTS.md 这类指令文件、记忆插件的记忆文件），点一个在文件面板里打开（会话读不到的文件，比如工作目录外的，打不开）；接近上限时多一句提醒。本次启动后这个会话还没发过请求时没有分段，已用的整个写成「上一次请求」一行。

新对话（还没发第一条消息）、会话里还没有一条写完的回复、或者没有可用的模型时，圆环不显示。

## 数字怎么算

总数来自服务商在每条回复上报的用量；各段是宿主估的，再缩放到这个总数。

- **上下文占用**：最近一条写完的回复背后那次请求的「输入 + 缓存读取 + 缓存写入 + 输出」。前三项是那次请求发出去的全部（系统提示词、工具表都在里面），输出下一轮也要带回去。有重试时按最后成功的那一次算，丢掉的几次不共用这个窗口。分母是下一轮要用的模型的上下文窗口。
  - 这是「上一次请求」的大小：之后新来的工具结果、你刚写的话还没算进去，压缩完到下一条回复之前也还是压缩前的数。
- **各段**：宿主在发请求时按那份请求估（约 3.5 个字符一个 token），再按上面的总数等比缩放，所以各段加起来正好是总数。服务商只报总数，各段只能是估的。

token 数写成 812、12.3k、4.1M 这样，每一档留一位小数。

## 用法

随应用发，不用安装，也不能停用。会话还没有回复时不画圆环。
