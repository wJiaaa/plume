# 建议新会话

模型做着一件事时看到另一件值得做、但不该塞进这次改动的事（没人用的代码、过时的文档、缺的测试、顺手发现的安全问题），不自己动手，也不派一个你看不见的子 Agent，而是在对话里放一张卡片，问你要不要另开一个会话去做。

## 它做了什么

- **`spawn_session`**：模型提一条建议，写清标题、为什么现在提、新会话要做什么，再写好新会话的第一句话（自成一体：文件路径、上下文都在里面，不靠这个对话）。当场返回，什么都没开始，模型接着做手上的事。
- **卡片**：建议画在对话里调用的位置：标题、一两句理由和右上角的收起；下面一排和输入框的排法一样，左边是工作树开关和交回开关（只有图标，开着时染强调色），右边是模型、思考档位和「开始」按钮。工作树开关只在这个对话属于 Git 项目时出现。参数还在写时只是一行「建议新会话 · 标题」。
- **模型和思考档位**：和输入框右下角那两枚一样。一开始是默认模型和默认推理强度，不动就按默认的开；选了别的，新会话就用选的。
- **开始**：在这个对话所在的项目里（不在项目里时是它的目录）开一个新会话，叫建议的标题，第一句是模型写好的那段话；侧栏里挂在这个对话下面。卡片缩成一行「新会话 · 标题」，那个会话在跑时扫光，没跑完时标红，点了过去。当前对话不动。
- **工作树**：打开时，新会话在它自己的 Git 工作树和分支里跑，不动项目的检出，几个会话同时改同一个仓库也不互相踩；之后在它的工作树签上合回去（见 Git）。模型说这件事会和别的会话同时改同一个仓库时（你让它把一件事拆给几个会话），开关一开始就开着，你也能在卡片上改。
- **收起**：卡片缩成一行「建议了新会话 · 标题 · 已收起」，不再催你。只记在这台机器上，建议本身还在记录里。
- **交回这里**：打开时，新会话跑完第一轮、手上的事都回来了（它派出去的子 Agent、后台命令）以后，把它最后那段回复送回这个对话，对话里多一行「来自新会话 · 标题」，并叫起这个对话接着做。模型在你让它把一件事拆给几个会话时会打开它，你也能在卡片上改；开始以后、第一轮还在跑时，那一行后面还挂着这个开关。
- **`archive_session`**：你说「做完就归档」这类话时，模型把最后的回复写完、再调它，这个对话就在这一轮做完后归档，界面离开它。模型不会自己想归档就归档。
- **环境卡片**：「建议的新会话」一节列出这个对话里还没决定的建议（只列标题和理由，点一条滚回对话里那张卡片，选模型、开始都在卡片上）和开始了的会话在做什么。卡片收着时，还有没决定的建议，标题栏的环境开关上挂一个圆点。

## 边界

- 只交第一轮：之后你在新会话里接着聊，不会再往回送。被你停下的不交；出错、跑到上限的照样交，标成「没跑完」。
- 交回只在应用开着时记得：第一轮还没跑完就退出应用，那一轮也停了，不再交。
- 子 Agent 和侧边聊天里用不了：它们不是侧栏里的对话，替它们画的卡片没处画，替它们归档的会是派它们来的那个对话。
- 归档不当场做：那会把正在说话的这一轮砍掉，所以这一轮停在这一下、收场之后再归档。这一轮要是被你停下或出了错，就不归档。想找回来：设置 › 已归档的聊天。

## 用法

随应用发，不用设置。也可以直接说：

> 把这三块拆成三个会话分头做，做完交回来，我在这里看结果。

> 修好就把这个对话归档。
