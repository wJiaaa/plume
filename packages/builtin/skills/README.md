# 技能

输入框输入 `@` 可搜索技能；选中后插入 `/skill:名字`，继续写要求并发送即可。

把做某类事的步骤写成技能，Agent 看到任务对得上时自己拿来用；也可以在输入框里敲 `/技能名` 点名让它用。

## 它做了什么

- **技能目录**：每一轮把可用技能的名字和描述列进系统提示词。正文不放进去，Agent 调 `skill` 工具时才交给它，几十个技能也不占多少上下文。
- **`/` 菜单**：每个技能也是一条命令，`/技能名 补充说明` 发出去的是「用这个技能」和你的补充说明。话里也可以点名：「帮我 /skill:pdf 处理一下这个文件」。
- **`skill://` 地址**：Agent 能用 read 读 `skill://技能名`（正文）、`skill://技能名/`（目录里有什么）、`skill://技能名/references/x.md`（目录里的文件），ls 也认；只读，出不去技能目录。
- **同一份正文只给一次**：上下文里已经有这个技能的正文时，再调一次只提醒 Agent 照上面的做；压缩掉以后能重新给。
- **「插件市场 › 技能」**：按目录列出个人的和别的插件带来的技能；在上方选一个项目，连那个项目里的技能一起列，可以开关、打开 `SKILL.md`、删除（整个目录移到废纸篓；插件带来的随插件装卸，不能在这里删）。哪个技能没能加载、哪个描述太短，这里都会标出来。被同名的盖住的单列一块：能看两份差在哪，点「改用那个」就换成它生效。关掉的技能不进目录、工具和菜单。

## 技能放在哪

| 目录 | 来源 |
| --- | --- |
| `<项目>/.plume/skills` | 项目 |
| `<项目>/.claude/skills` | 项目 |
| `<项目>/.agents/skills` | 项目 |
| `~/.plume/skills` | 个人 |
| 装着的插件目录下的 `skills/` | 插件 |
| `~/.agents/skills` | 个人 |

技能插件自己随包带一个 `plume-plugin`（写 Plume 插件用的那份，正本在 Plume 仓库根目录的 `skills/plume-plugin`，构建插件时复制进来）：「插件市场」页右上角「创建插件 › 新建插件」开一个新对话，输入框里放好 `/plume-plugin`。

同名时排在前面的生效：项目的先于个人的，自己写的先于插件带来的；在设置页点过「改用那个」的，按你选的。设置页拿不到当前项目，只列个人的和插件带来的技能；项目里的技能照样给 Agent 和 `/` 菜单用。

## 写法

一个技能是一个目录，目录里放 `SKILL.md` 和它要用到的脚本、模板：

```markdown
---
name: pdf
description: 填 PDF 表单、抽出 PDF 里的文字。用户给了 PDF 文件、要读或要填时用。
---

1. 先用 `python ${CLAUDE_SKILL_DIR}/scripts/fields.py <文件>` 列出表单字段……
```

- `name` 只能用小写字母、数字和连字符，不写就用目录名。
- `description` 必填，Agent 靠它决定什么时候用；说清「做什么、什么情况下用」，通常要 40 个字符以上，最多 1024 个。
- `disable-model-invocation: true`：不列给 Agent 自己挑，只能从 `/` 菜单点名。
- 正文里的相对路径从技能目录算；`${CLAUDE_SKILL_DIR}` 会换成技能目录的绝对路径，`${CLAUDE_PLUGIN_ROOT}` 换成带来它的插件的目录（不是插件带来的就是技能目录）。
- `allowed-tools`：读了不用。Claude Code 里它是「这些工具不用再问」的名单，不是限制；Plume 的批准另有权限档管。

技能每一轮都现读，改完下一轮就生效。
