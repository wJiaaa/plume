# 密钥加密

插件要存的密钥（MCP 服务的令牌、请求头里的凭据、OAuth 登录拿到的令牌）不再以明文写在插件的配置里：交给这个插件加密成一段文本，插件再把这段文本写回自己的配置。

## 它做了什么

- **服务 `secrets`**：`seal(value)` 加密一个值，返回带 `plume-sealed:v1:` 前缀的文本；`unseal(sealed)` 解回来；`isSealed(value)` 认出一段文本是不是密文。别的插件（包括第三方插件）在 `inject` 里写上 `secrets` 就能用。
- **钥匙**：AES-256-GCM，32 字节的钥匙存在这个插件的数据目录里（`plugin-data/plume.secrets/vault.key`，只有你能读），第一次加密时生成。
- **只加解密，不替插件存**：密文跟着它所属的那条配置走，删掉配置就是删掉密钥。

## 边界

- 挡的是配置文件被同步、拷走、贴进问题报告时带出明文；挡不住这台机器上以你的身份运行的程序：钥匙就在密文旁边，插件也都跑在同一个进程里。
- 钥匙丢了（删掉了数据目录里的 `vault.key`），之前加密的值都打不开，用到它们的插件会把它们当成没填、请你重新填；钥匙文件在却读不出来时会报错，不会换一把新的盖掉它。
- 不用系统钥匙串：现在的安装包签名每个版本都不同，钥匙串会在每次更新后要你重新授权。
