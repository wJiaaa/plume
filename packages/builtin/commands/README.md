# 命令

把常用的指令写成 Markdown 文件，在输入框里敲 `/名字` 就能发出去，不用每次重打一遍。

## 它做了什么

- **`/` 菜单里的命令**：从四个目录读命令文件，供给输入框的 `/` 菜单。发送时把命令展开成文件正文，对话里显示的就是发给 agent 的全文。
- **`/commands`**：不发消息，打开设置里的「命令」页（在「Agent 能力」组里）。同名的命令文件被它盖住。
- **设置页「命令」**：顶上选看个人的还是某个项目的命令，列出那一层的命令，可以新建（存进项目还是个人目录可选）、打开编辑、删除（文件移到废纸篓），也能直接打开对应的命令目录。下面另有只读的「内置」一段，列出产品和插件自己带的命令（`/clear`、`/compact`、`/commands`，装了对应插件时还有 `/plan`、`/btw`、`/review`），经 `ui.listCommands` 读。哪个文件没能加载、哪个被同名的盖住了，这里都会标出来。

## 命令放在哪

| 目录 | 来源 |
| --- | --- |
| `<项目>/.plume/commands` | 项目 |
| `~/.plume/commands` | 个人 |
| `<项目>/.claude/commands` | Claude · 项目 |
| `~/.claude/commands` | Claude · 个人 |

同名时排在前面的生效：项目的先于个人的，Plume 的先于 Claude 的。子目录是命名空间：`git/commit.md` 叫 `/git:commit`。名字只能用小写字母、数字和连字符。设置页看项目时列的是那个项目的两个目录，新建的项目命令写进 `<项目>/.plume/commands`，不往 `.claude` 里写。

## 写法

```markdown
---
description: 审一遍改动，一句话说明它做什么
argument-hint: <文件或目录>
---

审一下 $ARGUMENTS 里的改动，先说结论再说依据。
```

- `description` 显示在菜单里，`argument-hint` 在还没写参数时以灰字提示。
- 正文里 `$ARGUMENTS`（或 `$@`）代表命令后面打的全部内容，`$1`、`$2` 分别取第一个、第二个参数（引号可以把几个词括成一个）。
- 一个占位符都没写时，命令后面打的内容接在正文末尾。
- `deliver`：可选，决定 Agent 正在干活时这条命令怎么送出。`prompt`（默认）和 `followUp` 排到当前这一轮之后；`steer` 直接插进正在跑的这一轮，适合「只看 src/」这类纠偏。空闲时三者一样。

命令文件每次打开菜单、每次发送都现读，改完马上生效。
