# 计划模式

先看清楚、交一份计划，你批准之前不改任何文件。

## 它做了什么

- **开关**：输入框底下、权限旁边的计划模式开关，按对话记；新对话里拨了，第一句话发出去时跟着建出来的对话。`/plan` 也是这个开关，`/plan 要规划的事` 先进计划模式再把后半句发出去。
- **不改文件**：开着时写、改文件的工具（内置的 `write`、`edit`，别的插件声明成写、改文件的也算）直接拒绝；命令一律在只读沙箱里跑（和权限档无关，完全访问也一样），申请离开沙箱的不跑。联网、别的插件的工具照常。这个对话派出去的子 Agent、侧边聊天也受同一道线。
- **交计划**：模型用 `submit_plan` 交一份 Markdown 计划，对话里接着这一轮的回复出现计划卡（不铺满整栏；上面一条是「Plume 提出了一个计划」和计划的标题、倒计时和「打开计划」，下面一排动作；「等你批准计划」由运行行说），完全访问也不替你批；对话里这一下读作「提交计划 标题」，等你拍板时扫着光说「正在提交计划」。
  - **接受**（⌘↵）：计划模式就地关掉，同一轮里接着做；请求批准档下还有「接受并开启自动模式」，先切到帮我批准再接着做。
  - **在新会话里执行**：计划连同评论存成文件，在同一个项目里开一个只带着这份计划的新会话去实施，这个对话就此停下，留着回答那边的提问；按钮旁的箭头给新会话挑模型，不挑用默认模型。新会话的第一句话让它拿不准计划的意图时不要猜：有办法读、问这个对话就先回来找，没有就问人；怎么读、怎么问由提供这些工具的插件自己告诉它（比如会话互通按新会话记着的来处说明），计划模式不点名别的插件的工具。
  - **修改…**（Esc）：写下要怎么改，模型照着改完再交。
  - **拒绝**：这一轮停下，等你说下一步。
- **计划文件**：每份计划一交上来就存进对话的临时目录（`plans/plan-<年月日-时分秒>.md`），批准时带着注意事项重写同一个文件，压缩以后模型照样能重读。
- **计划面板**：交计划时右栏自动打开一次。顶上一条固定的栏：计划文件的路径（批准过好几份时点它切换），右边「在编辑器中打开」（应用图标和一枚箭头，箭头换用哪个应用）和 `</>`（看 Markdown 原文）；下面直接是计划正文，不套卡片，按文档排版渲染（标题档拉开，照 t3code 计划卡的正文），切到 Markdown 原文同样直接摊开、不套卡片边框也不限高，照常折行；正文一列照 t3code 的 Markdown 文件预览，最宽 896px，面板宽了居中。等审批时划一段字就能留评论，评论按序号列在计划卡上：点「修订」连同补充的话一起发回去改；直接接受时评论作为「执行时注意」随计划交出去，计划不重写。批准过好几份时点顶栏的文件路径切换着看；环境卡片的「计划」一节逐份列出批准过的计划，点一行在面板里摊开那一份。
- **压缩后不丢**：上下文压缩把批准计划那一段概括掉时，批准的计划原样接在摘要头里（交给新会话的那份写明不在这里执行）。
- **给别的插件读**：服务 `session.plan` 告诉别的插件（比如审阅改动的）一个对话照着做的是哪份计划，连同注意事项；在新会话里执行的那份算新会话的，这个对话不再算它。
- **提示词**：开着时系统提示词多一段计划模式的规矩：先读透代码（范围大时并行派只读子智能体去查）、问早问齐、把接口和数据、边界和失败、怎么证明做成了都定下来、交之前对着代码复核；计划按标题、背景（含查到的现状，带 `path:line`）、改动（只写推荐的做法，每条写到具体做法，点名关键文件和可复用的函数）、验证（命令、测试和要试的场景）、假设来写；一轮查过东西却把方案写在正文里、没交计划时提醒一次。

## 用法

随应用发，不用配置：点输入框底下的计划模式开关，或者发 `/plan`。
